# Парсер литературных статей для Telegram

## Бот автопостинга (`bot.py`)

Бот сам проверяет сайты, копит статьи в очереди и публикует их в канал
по одной с интервалом — без ручного запуска.

### Первый запуск

1. У @BotFather: `/newbot` → получите токен.
2. Добавьте бота **администратором** канала с правом «Публикация сообщений».
3. В `config.yaml`: `telegram.chat_id: "@ваш_канал"` (или числовой id `-100…`).
4. Положите токен в файл `token.txt` рядом с `bot.py` (или в переменную `TELEGRAM_BOT_TOKEN`).
5. Запустите `start_bot.bat` (или `python bot.py`).
6. Напишите боту в личку `/start` — он пришлёт ваш id. Впишите его в
   `bot.admins: [123456789]` и перезапустите бота.

### Настройки (секция `bot:` в `config.yaml`)

| Параметр | Что значит |
|---|---|
| `admins` | id тех, кто управляет ботом |
| `check_every_min` | как часто проверять сайты |
| `post_every_min` | интервал между постами в канале |
| `quiet_hours` | ночью не публиковать, например `"23:00-08:00"` |
| `moderation` | `true` — статьи сначала приходят админам с кнопками «В очередь / Сейчас / Пропустить» |
| `max_queue` | максимум статей в очереди (остаются самые свежие) |

### Текст поста

Под заголовком бот ставит первые абзацы самой статьи (секция `telegram:`):

| Параметр | Что значит |
|---|---|
| `summary` | `lead` — первые абзацы статьи, `anons` — анонс, который отдаёт сайт |
| `summary_chars` | примерная длина текста (обрезается по границе слова) |

Если в пост попадает мусор (плашка сайта, подпись, биография автора) —
добавьте начало такого абзаца в `lead_skip` в `config.yaml`.

### Темы канала

Бот собирает новости четырёх тем (секция `topics` в `config.yaml`):
литература (#литература), классическая музыка (#классика), джаз (#джаз)
и культура (#культура). Хэштег темы ставится первым в каждом посте.

- Профильные сайты (`topic: …`) дают статьи сразу с темой.
- Общие ленты (`filter: true`) — тема определяется по ключевым словам;
  с `fallback_topic: culture` остальное идёт в «культуру».
- «Культура» — запасная тема (`generic: true`): статья попадает туда, только
  если не подошли джаз, классика или литература. Поп- и рок-музыка и светская
  хроника в неё не берутся (`exclude` у темы).
- Посты чередуются по темам: следующей выходит тема, которой дольше всех не было.
- В очереди держится до `max_queue` статей каждой темы.

### Модерация

`bot.moderation: true` — ничего не публикуется без одобрения. Бот присылает вам
статьи с кнопками **✅ В очередь / ⚡ Сейчас / ❌ Пропустить**, по `review_per_topic`
(3) на тему одновременно, считая уже одобренные. Новые кандидаты приходят, когда
одобренные выходят в канал или вы что-то пропускаете. На GitHub кнопки
срабатывают при следующем запуске (до 15 минут). Если долго не отвечать —
в канале ничего не выходит.

### Проверка по реестрам

Раз в сутки (`registry_check`) бот сверяет все источники со списками:
экстремистских организаций (официальный перечень Минюста), иностранных агентов
и нежелательных организаций (по Википедии — официальный реестр Минюста
с сервера бота недоступен). Найденный источник сразу отключается, его
неопубликованные статьи снимаются, вам приходит сообщение. `/registry` —
результаты последней проверки.

Это сигнал тревоги, а не юридическая гарантия: Википедия может отставать,
а статус авторов отдельных статей бот не проверяет. Ложное срабатывание
(после проверки по официальному реестру) — `registry_ok: true` у источника;
другие названия источника для сверки — `aliases`, другие сайты — `domains`.

### Рубрики (хэштеги)

Каждый пост получает до `max_rubrics` рубрик (#рецензия, #фрагмент, #поэзия,
#премии…) плюс общий `hashtags`. Правила — в секции `rubrics` в `config.yaml`:
по части ссылки (`url`), словам в заголовке (`words`) или источнику (`sources`).
Чтобы добавить рубрику, допишите блок с `tag` и нужными правилами.

### Еженедельный дайджест

Секция `digest`: по воскресеньям в 19:00 бот публикует 5 лучших постов недели
одним сообщением. «Лучшие» — по реакциям подписчиков в канале (бот собирает их
сам; нужно, чтобы реакции в канале были включены). Пока реакций нет — самые
свежие, не больше 2 с одного сайта. `/digest` — посмотреть заранее (придёт только вам).

### Команды в личке с ботом

`/status`, `/queue`, `/check`, `/post` (опубликовать следующий сейчас),
`/skip`, `/digest`, `/registry`, `/pause`, `/resume`.

Бот работает, пока открыто окно / включён компьютер. Для работы 24/7 —
GitHub Actions (ниже) или сервер (VPS).

## Запуск на GitHub Actions (без своего компьютера)

GitHub каждые 15 минут запускает `python bot.py --once --state state.sql`:
бот разбирает команды, пришедшие в личку, раз в `check_every_min` проверяет
сайты, публикует пост, если подошло время, и сохраняет состояние в `state.sql`.

1. Создайте репозиторий на github.com (**New repository**). Лучше публичный:
   у публичных минуты Actions бесплатны без лимита, у приватных — 2000 мин/мес,
   а бот тратит ~3000. Токен в публичный репозиторий не попадёт (он в `.gitignore`
   и в секретах).
2. Загрузите папку в репозиторий (команды — в конце раздела).
3. **Settings → Secrets and variables → Actions → New repository secret**:
   имя `TELEGRAM_BOT_TOKEN`, значение — токен бота.
4. **Actions** → включите workflows → «Автопостинг» → **Run workflow**, чтобы
   проверить. Дальше он будет запускаться сам.
5. **Остановите бота на компьютере** — два бота одновременно будут публиковать
   одно и то же и мешать друг другу.

Особенности:
- Команды в личке работают, но ответ приходит при следующем запуске (до ~15 мин).
  Кнопки модерации тоже работают с этой задержкой.
- GitHub может запускать задачи с опозданием в нагруженное время.
- Если в репозитории 60 дней не было активности, GitHub отключает расписание —
  тогда включите его во вкладке Actions.
- Настройки меняются правкой `config.yaml` прямо на github.com.
- Пауза: команда `/pause` или **Actions → Автопостинг → ⋯ → Disable workflow**.

Загрузка в репозиторий (из папки проекта):

```
git remote add origin https://github.com/ВАШ_ЛОГИН/ИМЯ_РЕПОЗИТОРИЯ.git
git push -u origin main
```

## Парсер (`litparser.py`)

Собирает свежие статьи с литературных сайтов (RSS и HTML), отсеивает
нерелевантное по ключевым словам, убирает дубли и публикует в Telegram.

## Установка

```
pip install -r requirements.txt
```

## Запуск

| Команда | Что делает |
|---|---|
| `python litparser.py` | Показать найденное (ничего не запоминает) |
| `python litparser.py --init` | Первый запуск: запомнить всё текущее, чтобы не публиковать старьё |
| `python litparser.py --export posts.md` | Дописать подборку в Markdown-файл |
| `python litparser.py --send` | Отправить посты в Telegram |
| `python litparser.py --send --loop 60` | Проверять и отправлять каждые 60 минут |
| `-v` | Подробный лог |

## Telegram

1. Создайте бота у @BotFather, получите токен.
2. Добавьте бота админом в канал (или напишите ему в личку, чтобы получать черновики).
3. В `config.yaml` укажите `telegram.chat_id` (`@channel` или числовой id).
4. Задайте токен:
   - PowerShell: `$env:TELEGRAM_BOT_TOKEN = "123:ABC..."`
   - bash: `export TELEGRAM_BOT_TOKEN=123:ABC...`

Совет: сначала шлите в личный чат с ботом и пересылайте в канал лучшее вручную.

## Настройка источников (`config.yaml`)

RSS:
```yaml
- name: Год литературы
  type: rss
  url: https://godliteratury.ru/rss
  filter: false        # профильный сайт — фильтр не нужен
```

Сайт без RSS — указываем регулярку для ссылок на статьи:
```yaml
- name: Горький
  type: html
  url: https://gorky.media/
  link_pattern: '^https://gorky\.media/(reviews|context|fragments)/[^/]+/?$'
```

Для общих новостных лент ставьте `filter: true` — статья пройдёт, только если
в заголовке/анонсе нашлось `min_score` ключевых слов. Ключевые слова — начала
слов (`писател` → писатель, писателя…) или регулярки с префиксом `re:`
(в одинарных кавычках).

Уже обработанные ссылки хранятся в `seen.sqlite3` — удалите файл, чтобы начать заново.
